# Research: User Accounts

Decisions made while planning spec 001. Each resolves an unknown or a conflict between
existing docs.

## R1. Session mechanism
- **Decision**: Opaque 256-bit random token (`secrets.token_urlsafe(32)`) in an `httpOnly`,
  `SameSite=Lax` cookie named `habitude_session`; only the SHA-256 hash is stored.
- **Rationale**: ADR-2; server-side revocation (FR-005) and inactivity expiry (FR-004). Hashing
  means a leaked database cannot be replayed as sessions.
- **Alternatives**: JWT (no revocation without a denylist), server-signed cookies (extra secret).

## R2. Inactivity expiry
- **Decision**: `expires_at = last_used_at + 30 days`, refreshed on every authenticated
  request. An expired session is deleted when presented and the request gets `401`.
- **Rationale**: Directly encodes FR-004 with one indexed lookup; no background job.

## R3. Lockout (FR-007)
- **Decision**: Store failed attempts in `failed_login(email, attempted_at)`. Sign-in is locked
  when the 5 most recent failures for that email all fall within 15 minutes of each other and
  the latest is less than 15 minutes old. Attempts while locked are rejected with
  `429 LOCKED_OUT` and not recorded. A successful sign-in clears that email's failures.
  Failures are recorded for unknown emails too, so lockout does not reveal account existence.
- **Alternatives**: In-memory counter (lost on restart, not testable across app instances).

## R4. Password hashing
- **Decision**: argon2-cffi `PasswordHasher` defaults (argon2id). Unknown-email sign-ins still
  run one verification against a dummy hash to keep timing similar. Tests swap in a low-cost
  hasher for speed.
- **Password bounds**: minimum 10 (FR-001); maximum 128 characters as a DoS guard on hashing.
  This is a boundary validation, not a business rule, and is well above OWASP's 64 minimum.

## R5. Email handling
- **Decision**: Trim and lowercase before storage and lookup; unique index on the lowercase
  value. Validate with a minimal shape check (`local@domain.tld`, ≤ 254 chars) instead of adding
  `email-validator`; there is no email delivery in v1, so deliverability checks add no value.

## R6. Error envelope and codes
- **Decision**: `{"error": {"code", "message", "details"}}` with UPPER_SNAKE codes
  (`UNAUTHENTICATED`, `VALIDATION_ERROR`, `REGISTRATION_FAILED`, `INVALID_CREDENTIALS`,
  `LOCKED_OUT`, `FORBIDDEN`, `NOT_FOUND`).
- **Rationale**: `docs/architecture.md` and `docs/frontend.md` use UPPER_SNAKE while
  `docs/coding-standards.md` showed snake_case. Two of three docs and the frontend `ApiError`
  already use UPPER_SNAKE, so coding-standards is updated to match.
- Duplicate registration returns `400 REGISTRATION_FAILED` "Could not register" (FR-008).
  Wrong email or password returns `401 INVALID_CREDENTIALS` "Invalid email or password".

## R7. CSRF
- **Decision**: `SameSite=Lax` plus a required `X-Requested-With` header on POST/PUT/PATCH/DELETE
  under `/api`, enforced by middleware (coding standards §7). Missing header → `403 FORBIDDEN`.

## R8. Clock and time
- **Decision**: `core/clock.py` defines a `Clock` protocol with `now() -> datetime` (aware UTC),
  `SystemClock`, the `get_clock` dependency, and `local_date(now_utc, tz)`. Tests override
  `get_clock` with a `FrozenClock` that can `advance()`.
- SQLite drops tzinfo, so a `UTCDateTime` `TypeDecorator` in `core/db.py` stores UTC and returns
  aware datetimes.

## R9. IDs
- **Decision**: UUIDv7 strings generated by a ~10-line helper in `core/ids.py`; Python 3.13 has no
  stdlib `uuid7` and a dependency for it is not justified.

## R10. Test database
- **Decision**: A session-scoped fixture runs `alembic upgrade head` once into a template SQLite
  file; each test copies it into its own `tmp_path`. This exercises migrations (testing.md §3)
  while keeping each test isolated and fast.
- Tests use FastAPI's synchronous `TestClient` (httpx under the hood), which avoids
  `pytest-asyncio` since all routes are sync.

## R11. Timezone at registration
- **Decision**: The frontend sends `Intl.DateTimeFormat().resolvedOptions().timeZone`; the
  backend validates it with `zoneinfo` and falls back to `UTC` when omitted. Invalid names are
  a `422`.

## R12. Frontend auth state
- **Decision**: No `AuthProvider`; the `['me']` TanStack Query is the auth state (ADR-6). A 401
  from any query sets `['me']` to `null`, which makes `ProtectedRoute` redirect to
  `/sign-in?next=<path>`.
- Generated API types are used as-is (snake_case) instead of mapping to camelCase: one source of
  truth, no mapping layer to maintain. `docs/coding-standards.md` is updated accordingly.

## R13. Backend module layout
- **Decision**: Follow `docs/coding-standards.md` (`core/`, `models/`, `schemas/`, `services/`,
  `routers/`, `migrations/`) instead of the `api/v1/` tree sketched in architecture.md.
