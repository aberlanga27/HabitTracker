# Feature Specifications

This folder holds every Spec Kit feature specification for Habitude. Each feature lives in its own numbered folder:

```
docs/specs/NNN-feature-name/
├── spec.md        # WHAT and WHY — written by /speckit-specify (human-reviewed)
├── plan.md        # HOW — written by /speckit-plan
├── research.md    # decisions and alternatives considered (from /speckit-plan)
├── data-model.md  # entities and relationships (from /speckit-plan)
├── contracts/     # API contracts, e.g. OpenAPI fragments (from /speckit-plan)
├── tasks.md       # ordered, testable tasks — written by /speckit-tasks
└── checklists/    # quality checklists — written by /speckit-checklist (optional)
```

Status values are `Draft` (written), `Clarified` (ambiguities resolved), `Planned` (plan.md and tasks.md exist), and `Implemented` (merged with tests). Only `spec.md` exists for features still in `Draft`. The sibling files are generated by the Spec Kit skills installed in `.github/skills/` when a feature moves from Draft to planning. Numbering is sequential and never reused. The constitution in `.specify/memory/constitution.md` governs every document here.

**Tiers**: *MVP* is the smallest set that makes the app usable end to end. *Core* rounds out the everyday experience. *Nice-to-have* can ship after the first release without hurting the demo.

## Dependencies

Build in roughly this order; a spec should not enter `/speckit-plan` before the specs it depends on have an accepted plan.

| Spec | Depends on | Why |
|------|-----------|-----|
| 001 User Accounts | — | Root of everything; provides the User and Session. |
| 002 Habit Management | 001 | Habits are owned by a User. |
| 003 Daily Check-In | 001, 002 | Check-ins attach to Habits; "today" uses the user's timezone. |
| 004 Streak Tracking | 003, 005 | Streaks are derived from check-ins and must skip non-scheduled days. |
| 005 Habit Schedules | 002 | Schedules belong to Habits. |
| 006 Today Dashboard | 002, 003, 005 | Lists due habits and toggles check-ins; shows streaks from 004 when available. |
| 007 History Calendar | 003, 005 | Cell status needs check-ins and due/not-due per day. |
| 008 Reminders | 002, 003, 005, 012 | Fires only for due, incomplete habits; permission opt-in lives in settings. |
| 009 Stats & Insights | 003, 005, 012 | Rates are computed over scheduled days in the user's timezone and week start. |
| 010 Categories & Tags | 002, 006 | Extends Habit with a category; adds filters to Today and All Habits. |
| 011 Data Export & Import | 002, 003, 005, 008, 010 | The export bundle contains all of these entities. |
| 012 Settings & Preferences | 001 | Timezone, week start, theme, and notification flag hang off the User. |
| 013 PR Analysis Pipeline | none (cross-cutting) | Enforces constitution gates on every PR; jobs skip until the tooling from 001–006 exists. |

Cross-cutting: spec 012 (timezone and week start) is read by 003, 004, 005, 007, and 009. Plan 012's data model early, even though its UI can ship later.
